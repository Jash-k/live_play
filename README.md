# live_play — Tamil + sports + Bigg Boss live playlist

Automatically refreshed M3U playlist of **Tamil-language channels**, **Tamil/English sports feeds**
and **Bigg Boss Tamil 24/7**, built from community sources.

**Subscribe URL (main feed)**

```
https://raw.githubusercontent.com/Jash-k/live_play/main/jash-live.m3u
```

Everything in this repo is generated by `scripts/curate-live.mjs`, which runs every 2 hours in
GitHub Actions. Community metadata is aggregated — playback and content rights are **not**
verified by this project.

---

## What is in the feed

| Group | Contents |
|---|---|
| `Bigg Boss Tamil 24/7` | Tamil-labelled Bigg Boss 24/7 feeds only |
| `Tamil - Entertainment / News / Movies / Music / Kids / Comedy / Devotional / Lifestyle / Infotainment / General` | Every Tamil-language channel found in the sources |
| `Sports - <brand> - Tamil / English` | Star Sports, Sony Sports, FanCode, Willow, Cricbuzz, CricHD, Prime Sports, Ten Sports, DD Sports, Sports18 |

Rules the curator enforces:

* **Tamil detection** uses three independent signals: an explicit `tvg-language="Tamil"`, a
  language-style `group-title` (e.g. JioTV's `group="Tamil"`), or a channel-brand match from the
  editable brand table in `scripts/curate-live.config.json`.
* **No guessing.** A sports feed that upstream never labels Tamil/English is *not* relabelled —
  it goes to `jash-review.m3u` instead. The only exception is the explicit
  `sports.assertedEnglish` list (Star Sports 1/2, Sony Ten 1/2/5, Willow, CricHD, Cricbuzz,
  Sports18, Ten Sports) — every row accepted that way is counted as `assertedLanguage` in the stats
  file so you can see exactly how many came from the assertion rather than an upstream label.
* **Excluded on purpose:** non-Tamil regional languages (Hindi, Telugu, Malayalam, …), radio/FM and
  audio-only streams (`includeRadio: false`), junk names, raw `.ts`/`.flv` URLs, non-HTTPS URLs,
  expired tokens (`exp=`/`expires=`/`expires_in`), and duplicate streams.
* **Alternate streams** of the same channel are kept up to `maxAlternatesPerChannel` (default 3) so
  one brand cannot flood the list; the copy carrying playback metadata (clearkey, user-agent,
  cookie) is preferred.
* Playback properties (`#KODIPROP`, `#EXTVLCOPT`, `#EXTHTTP`) are copied **unchanged** from the
  source. The curator never obtains keys, converts DRM or authenticates on your behalf.

## Files

| File | Purpose |
|---|---|
| `jash-live.m3u` | Main feed — subscribe to this |
| `jash-review.m3u` | Sports rows whose language upstream does not state. Not in the main feed |
| `jash-live.stats.json` | Machine-readable report: per-source results, drop reasons, group counts, discovery |
| `jash-review.json` | Review queue without stream secrets (name, family, reason, source) |
| `CHANNEL-SUMMARY.md` | Human-readable summary, regenerated on every run |

## Sources

1. **Community source index** — <https://playlists.dbprojects.workers.dev/api/sources>.
   `/api/sources` returns `{id, name, category, url, type}` rows. Sources listed in
   `index.pinned` are always fetched (`jiotv_32`, `jiotv_8`, `jiotv_20`, `jiotv_16`, `jiotv_36`,
   `jiotv_18`, `jiotv_28`, `star_3`, `special`, `sonytv_4`, `mix_channels`, `yupptv_one`,
   `yupptv_two`, `fancode_*`, `prime_sports_one`, `willow_one`, `crichd`).
   Every other row is a **discovery candidate**: it is merged only if it actually yields Tamil
   channels (`autoDiscoverMinTamil`) or Tamil/English sports (`autoDiscoverMinSports`), so new
   providers added upstream are picked up automatically while dead rows stay out.
2. **Legacy raw-GitHub playlists** — `maybetv/Jo` and `sportlive18/Sportlink-wtf` (unchanged from
   the previous version, listed under `legacySources`).

Both the M3U and the JSON source shapes are supported: JioTV channel dumps
(`[{name, url|mpd_url, keyId/key|license_url, headers, expires_in}]`) and event dumps
(FanCode/SonyLIV `{matches:[…]}`). Event rows without a stream URL are skipped.

## Local usage

```bash
node scripts/test-curate-live.mjs   # offline fixture tests (no network)
node scripts/curate-live.mjs        # refresh the playlists in the repo root
node scripts/validate.mjs --dir .   # structural validation of the output
# or
npm run check
```

Useful flags / env vars:

```bash
node scripts/curate-live.mjs --config other-config.json --out /tmp/out --snapshot fixtures/
INDEX_URL=https://example.com/api/sources node scripts/curate-live.mjs   # different index
SOURCE_SNAPSHOT_DIR=fixtures OUTPUT_DIR=/tmp/out node scripts/curate-live.mjs
```

`--snapshot` reads sources from local files named `<source-id>.m3u` / `<source-id>.json` plus an
`_index.json`, which is how the test suite runs without network access.

## Configuration

Everything tunable lives in `scripts/curate-live.config.json`:

* `index.pinned` / `index.autoDiscover*` — which index sources are always used, and how aggressive
  discovery is.
* `tamil.brands` — the brand table (category → brand names). Add a channel here to teach the
  curator a new Tamil brand; no code change needed.
* `tamil.denyBrands` — non-Tamil brands that keep appearing inside Tamil-labelled upstream lists.
* `tamil.includeRadio`, `tamil.radioPattern` — radio/FM handling.
* `filters.junkNamePattern` — names such as `… test`, `promo`, `sample` that are never published.
* `sports.languages`, `sports.families`, `sports.assertedEnglish` — which sports brands are kept,
  in which languages, and which ones are known to be English without a label.
* `safety.minMainEntries`, `safety.minOkSources`, `safety.maxAlternatesPerChannel`,
  `safety.concurrency`, `safety.timeoutMs` — guard rails. If a refresh would publish a feed that
  fails the minimums, the job **fails and leaves the previous playlist untouched**.

## Adding a channel that is missing

1. Add the brand to the right category in `tamil.brands` (or the family in `sports.families`).
2. If it only exists in a source that is not pinned, either wait for auto-discovery or add its
   index id to `index.pinned`.
3. Run `npm run check` and commit.

## Limitations

* Community metadata is not proof of the real audio language, and streams disappear, rotate tokens
  or become geo-blocked without notice.
* Playback was not tested: some entries need a specific player, DRM settings, a user-agent or
  legitimate access to the upstream service.
* Bigg Boss Tamil availability depends on the upstream 24/7 feed; the group is simply absent when
  no Tamil-labelled feed is found during a refresh (the job does not invent one).
* FanCode/SonyLIV event feeds appear and disappear with the live schedule.

This repository curates links that are already public; it does not host or re-stream content, and it
grants no rights to anything listed. Use responsibly and respect the terms of the upstream services.
